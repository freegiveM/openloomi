## 4. 下一步（**接手人操作顺序**）

### 4.1 第一步：让探针积累证据

1. **不必重启 OpenLoomi**——turbopack dev 会 hot-reload `route.ts`。
2. 开 powershell 跑一次 §3.1 命令（per-task 30 min timeout 给够）。
3. 等 5-10 分钟后看 `agent_api_probe.log` 里**到底走了哪些行**：

```
SSE start(controller) entered; generatorSymbol=fn
heartbeat-tick
heartbeat-tick
for-await loop entered
for-await got message #1 type=session keys=sessionId,messageId
#1 calling controller.enqueue(89B)
#1 controller.enqueue returned
```

**最关键的问题**：

| 探针显示的现象 | 结论 |
|---|---|
| `for-await got message #N` 出现 N>1 多次 | OpenLoomi 在 yield 多次，**问题在下游**（route.ts 把 chunk flush 给 client） |
| 只有 `for-await got message #1 type=session`，后续再无 mid-stream message | OpenLoomi **根本没 yield**后续 message，可能卡在 `pumpQuery` 里 `await this.recordProviderObservation(...)` 或其他 await — 不是 publish 问题 |
| `#N calling controller.enqueue(B)` 之后**没有 `#N controller.enqueue returned`** | `controller.enqueue` 同步阻塞，root cause 在这里 |
| `for-await THREW: name=...` | OpenLoomi 抛错，需要看 stack |

**只有把 §4.1 的现象看清楚之后，再去回滚/保留 2.2 节的 OpenLoomi 改动**。

### 4.2 第二步：根据探针决定方向

**如果探针显示 OpenLoomi 一条 mid-stream message 都不 yield**：
- 说明 §2.2.B 的 fire-and-forget 没修对真问题。**需要继续追**：`session.ts` 里 `await this.recordProviderObservation(...)` 这一步、行 441 也是 await，可能某条更深的 await 卡了。
- 优先用 `subagent` 在 `apps/web` 跑全栈 trace、**带着 `agent_api_probe.log` 实测结果**而不是凭空推断。

**如果探针显示 OpenLoomi yield 了多次但 `#N controller.enqueue returned` 没打印**：
- 那就是 `controller.enqueue` 真的同步阻塞。改 route.ts，把 enqueue 包成 `await controller.enqueue(...)` 然后写到一个 `TransformStream`。
- **注意：`WHATWG stream 规范说 enqueue 是同步非阻塞的**——如果真阻塞，那是 Node / Next.js dev 的实现差异。

**如果探针显示一切都正确，但 client 仍收不到 frame**：
- 那 problem 在 Next.js dev 把 `ReadableStream` 写到 socket 之间。继续看 Next.js turbopack 源码。

### 4.3 第三步：实在不行就 fs polling fallback

如果上面 1-2 步都走不通，**最务实的 runner 侧回退**：
- Runner 每 30 s 扫一次 `workdir` 顶层 mtime。
- 看到新文件 + 60 s 静默 + 仍然没拿到 SSE `result` event → 把"自 t=N 之后新增的 top-level 文件"当 deliverable，**直接构造一个 fake handle 走 `summariseHandle(...)`，写出 run.json**。
- 缺 `tool_calls/turn_count/usage` 这些真实性数据，但 deliverables 列表大概率正确。

这套不依赖 OpenLoomi 推送任何东西。
